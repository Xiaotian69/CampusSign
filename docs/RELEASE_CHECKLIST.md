# 发布检查清单

- 检查 main 的工作区、全部可达提交、配置模板、双 Edition 和文档。
- 用独立虚拟环境安装 requirements.txt，运行 `python -m unittest test_desktop test_desktop_ui -v`。
- 扫描 Git 文件及历史内容和提交元数据；人工检查截图。私人配置、日志、构建目录和备份不提交。
- README 的版本与下载链接应与 Release 一致；SCUFE 与 Generic 共用核心。
- 上传前检查文件及提交隐私；发布后从远端重新获取 main 和发行包再次检查。
- 仅在维护者明确授权后公开仓库并创建 Tag / Release。

## 真实签到验收

1. 使用单独的测试目录和自己的测试账号，分别启动两个 Edition。
2. SCUFE 确认预设地点和资料入口；Generic 确认空地点库，自行添加地点。
3. 在自己创建或获准测试的课程中发起位置签到，先执行“仅查询”，确认未提交。
4. 在允许签到的位置执行一次“查询并签到”，同时在学习通端核对活动、账号及成功状态。
5. 再次查询应跳过已签活动；测试未知地点、无活动及不支持类型的提示。
6. 关闭并重启，确认本机配置可恢复；分享结果前隐藏账号、课程及活动标识。
7. 离线测试不代表线上接口可用；验收通过后再单独决定构建、Release 与公开时间。

## 构建（验收后执行）

在独立 Windows 虚拟环境安装运行依赖与 PyInstaller，运行 `python build_release.py`。
同一个 `CxSign.exe` 配合不同的 edition 配置，生成：

- `CxSign-v1.0.0-SCUFE.zip`
- `CxSign-v1.0.0-Generic.zip`

构建仅复制白名单文件，不复制用户配置；构建完成后应再次检查 ZIP 清单和内容。
现有本地产物不代表当前代码已通过真实签到或发行验收。
